# Раздел «Настройки»

Профиль, управление учётными записями, справочники подсказок и журнал
действий. Бизнес-правила ролей — [`docs/requirements/access-control.md`](../../../../../docs/requirements/access-control.md),
устройство авторизации — [`ADR-004`](../../../../../docs/architecture/decisions/ADR-004-portal-auth.md).

## Файлы

| Файл | Назначение |
|---|---|
| `SettingsSection.tsx` | Оркестратор: композиция панелей, демо-переключатели |
| `TeamPanel.tsx` | «Команда и роли»: список, создание, редактирование, переключатель доступа |
| `UserFormModal.tsx` | Форма учётной записи (создание и редактирование) |
| `AuditLogPanel.tsx` | «Журнал действий»: последние 50 записей |
| `ImportHistoryPanel.tsx` | «История импортов потребности»: последние 50 загрузок Excel из раздела «Адреса», с деталями и отменой последнего импорта. Видна только руководителю, как «Команда и роли»/«Журнал действий» |
| `CandidateListsPanel.tsx` | Справочники подсказок для полей кандидата |
| `userForm.ts` | Чистая валидация формы (+ `userForm.test.ts`) |
| `SettingsSection.module.css` | Стили раздела: строки списков, чипы проектов, подписи под полями |

Кнопки-иконки (карандаш «изменить», стрелки порядка в справочниках) берутся
из `primitives.btnIcon` — у стрелок размер `btnIconXs`, чтобы строка списка
не становилась выше. Пока панель грузится, показывается `SkeletonLines`, а не
текст «Загрузка…».

## Что здесь настоящее, а что демонстрационное

Настоящее (Supabase): «Профиль» (текущая учётная запись, только чтение),
«Команда и роли», «Журнал действий», «Списки для кандидатов».

Демонстрационное: «Интеграции», «Уведомления», «Отображение» — переключатели
живут в состоянии страницы и **никуда не сохраняются**. Исключение —
«Плотность таблиц»: она реально влияет на интерфейс, но тоже не сохраняется
между сессиями.

## Правила работы с пользователями

- **Пароль недоступен на чтение.** В базе только bcrypt-хеш, ни одна функция
  его не возвращает. В форме есть лишь «задать новый»; пустое поле при
  редактировании означает «не менять».
- **Логин не редактируется** после создания — по нему связаны записи журнала.
  Уникальность проверяется во время ввода (`portal_admin_login_available`,
  дебаунс 400 мс) и гарантируется индексом в базе.
- **Удаления нет.** Только переключатель «Активен»: отключение обрывает
  открытые сессии пользователя, но сохраняет его и его историю.
- **Три панели видит только руководитель** — «Команда и роли», «Доступы» и
  «Журнал действий» рендерятся при `can("users")`. Координатор видит
  «Настройки» без них. Это удобство; по-настоящему запрет обеспечивают
  `portal_require_admin()` внутри каждой функции и закрытые RLS-таблицы.
- **«Доступы»** — матрица «раздел × роль» с тремя переключателями
  (`AccessPanel.tsx`, чистая логика — в `accessMatrix.ts`). Инвариант
  «Редактирование ⇒ Просмотр ⇒ Показывать» приводится в порядок до
  запроса (`normalizePermission`), чтобы пользователь не получал ошибку
  вместо ожидаемого результата. Ячейки «Настройки» и «Учётные записи» у
  руководителя заблокированы: сняв их, портал остался бы без пути к
  управлению правами. Изменение прав своей роли применяется к текущей
  сессии сразу, остальным — при следующей загрузке страницы.
- **«Все проекты»** в карточке пользователя — настоящий признак
  (`portal_users.all_projects`), а не «выбрать все существующие»: с ним
  сотруднику достаются и проекты, заведённые позже.
- **Себя отключить нельзя**, как и последнего активного руководителя —
  проверка в базе, в интерфейсе переключатель для своей строки задизейблен.

## Почему список пользователей не в `PortalContext`

Он нужен ровно одной панели и только одной роли. Класть его в глобальный
стор — значит на каждой загрузке портала делать запрос, который у трёх ролей
из четырёх закончится отказом. Тот же случай, что и с историей в
`DemandHistoryDrawer`: лениво, по месту использования.

## Известные ограничения

- Поле «Проекты» заполняется и отображается, но **данные по нему не
  фильтруются** — разграничения по проектам в модели доступа пока нет.
- Журнал показывает последние 50 записей без фильтров, поиска и постраничной
  навигации.
- Сотрудник не может сменить себе пароль сам — только через руководителя.
