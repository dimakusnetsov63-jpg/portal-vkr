# Раздел «Ставки»

Тарифы, по которым персонал работает у клиента: ставка за час/единицу/смену,
доход за смену/неделю/месяц (считается, не хранится), зарплатный проект,
бонусы, акции, условия оформления. Реальные данные Supabase
(`public.rate_cards` + `public.rates`).

Общий контекст — [`../../../../../CLAUDE.md`](../../../../../CLAUDE.md) и
[`docs/architecture/system.md`](../../../../../docs/architecture/system.md).
Бизнес-правила подробно — [`docs/requirements/rates.md`](../../../../../docs/requirements/rates.md).

## Два уровня, не плоская таблица

Структура снята с рабочей таблицы «ВКР Потребность.xlsx» (34 листа, по
листу на клиента), где строки идут блоками по городу с общими условиями на
блок (объединённые ячейки). Отсюда:

- **Блок условий** (`rate_cards`) — проект + город + юр. лицо: зарплатные
  проекты, бонусы, акции, надбавки, условия оформления, менеджер, работа
  офиса. Один раз на блок.
- **Строка тарифа** (`rates`) — должность внутри блока: ставки, единица
  измерения, график, дополнительные показатели. Связана с блоком настоящим
  FK (`rate_card_id`, `on delete cascade`) — переименование условий блока не
  требует правки каждой строки, удаление блока не оставляет сирот.

## Поток данных

```
RatesSection
  → usePortal(): rates, rateCards, ratesLoading, refreshRates,
                  addRate, saveRate, deleteRateRecord,
                  saveRateCard, deleteRateCardRecord,
                  selectedRateId, openRateDrawer, listOptions
  → joinRatesWithCards(rates, rateCards)   — соединение по rate_card_id, без доп. запросов
  → filterRates(joined, filters)
  → calculateRateMetrics(visibleRows)
  → <RatesDashboard> + <RatesTable> + <AddRateModal>
```

Компонент не обращается к Supabase напрямую — только через `usePortal()`.
CRUD выполняет `lib/supabase/ratesRepo.ts` (обычный `createClient()`),
вызываемый из `PortalContext`. Типы — `lib/supabase/rates.types.ts`,
выведены из `database.types.ts`, кроме `rates.extras` (в сгенерированном
типе — `Json`, приложение переопределяет его до `{id, label, value}[]`, тот
же приём, что `addresses.document_links`). `unit`/`schedule`/`office_status`
в БД — `CHECK`, не enum, поэтому в сгенерированном типе они `string`; узкие
литеральные типы (`RateUnit` и т. п.) сужаются на уровне приложения — тот же
приём, что `AddressStatus`.

`joinRatesWithCards` — единственное место, где плоские списки `rates` и
`rate_cards` сводятся в одну структуру `RateWithCard`. Это соединение на
клиенте, не дополнительный запрос: `listRateCards()`/`listRates()` — ровно
два запроса на весь раздел, без запроса на карточку (без N+1).

## Бизнес-правила (сводка)

- **Два уровня хранения**: условия — на блоке (`rate_cards`), тариф — на
  строке (`rates`), связь настоящим FK с каскадом.
- **Доход за смену/неделю/месяц не хранится** — считается в `rateMetrics.ts`
  из ставок и графика. Модель смен в неделю/месяц усреднённая (не
  воспроизводит индивидуальные множители исходной таблицы Excel).
  `rate_hour_priority` в сумму не входит — альтернативный тариф, не доплата.
  Для графиков без регулярной кадансации (`flexible`/`parttime`) — `null`,
  не `0`.
- **`project`/`legal_entity` — свободный текст со справочником**
  (`candidate_list_options`, новые `list_type`), не enum
  `candidate_project`: список клиентов «Ставок» шире, чем у остальных
  разделов.
- **Удаление — настоящее**, не soft-delete: у «Ставок» нет исторической
  ценности в устаревшем тарифе (как `staffing_demand`, в отличие от
  `candidates`/`addresses`). Удаление блока каскадом уносит его ставки —
  карточка предупреждает о их числе.
- **Раздел доступен всем четырём ролям** — как «Адреса»/«Уведомления».
- Все вычисления (фильтры/поиск/KPI/суммы) — на уже загруженных данных;
  повторный запрос к серверу только после create/update/delete.

## Безопасный порядок изменений

1. Найти затронутые файлы раздела и их использования (`PortalApp`, `index.ts`).
2. Прочитать оркестратор, чистую логику (`rateFilters.ts`/`rateMetrics.ts`),
   типы (`rates.types.ts`) и стили.
3. Логику фильтров/агрегации/join менять в `.ts`-файлах, а не в JSX.
4. Не менять публичный API компонентов и `usePortal()` без необходимости.
5. После изменения — `npx tsc --noEmit`, `npm run test`, затем `lint` и `build`.
6. Проверить в браузере (раздел за авторизацией).

## Известные ограничения

См. [`docs/requirements/rates.md`](../../../../../docs/requirements/rates.md#известные-ограничения) —
кратко: список проектов не синхронизирован с `candidate_project`, модель
смен в неделю/месяц усреднённая, нет истории изменений тарифа, подтверждение
удаления — нативный `window.confirm`, не модалка портала.
