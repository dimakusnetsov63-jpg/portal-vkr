# Требования: Ставки

Тарифы, по которым персонал работает у клиента: ставка за час/единицу/смену,
доход за смену/неделю/месяц, зарплатный проект, бонусы, акции и условия
оформления. Реализовано на реальных данных Supabase (TASK-008).

Техническое описание раздела —
[`src/components/portal/sections/rates/README.md`](../../src/components/portal/sections/rates/README.md),
схема таблиц — [`../database/schema.md`](../database/schema.md).

## Источник структуры

Рабочая таблица «ВКР Потребность.xlsx» — 34 листа, по листу на клиента
(Самокат, Купер, Лента, Магнит, Сберлогистика, Утконос и т. д.). Excel
использован **только как источник структуры** данных на этапе
проектирования: раздел работает с базой напрямую, импорта из Excel в
портале нет и не планируется.

## Общая концепция: два уровня

Внутри каждого листа Excel строки идут блоками по городу, и в каждом блоке
объединёнными ячейками заданы условия, общие для всех строк блока
(зарплатный проект, бонусы, акции, надбавки, менеджер, работа офиса).
Замер по одному из листов: 620 строк тарифа, 96 блоков, в среднем 6.5
строки на блок — и всего 13 уникальных текстов «Бонусы» на все 620 строк.

Отсюда раздел устроен в **два уровня**, а не как плоская таблица:

- **Блок условий** (`public.rate_cards`) — «проект + город + юр. лицо»:
  зарплатные проекты, бонусы, временные акции, надбавки, условия
  оформления, менеджер, работа офиса, примечания. Хранится **один раз** на
  блок.
- **Строка тарифа** (`public.rates`) — должность внутри блока: единица
  измерения, ставка за час (основная/приоритетная), сдельная часть, часов в
  смене, средняя надбавка за смену, график, дополнительные показатели,
  комментарий. Связана с блоком настоящим внешним ключом
  (`rate_card_id`, `on delete cascade`).

Плоская таблица (все условия колонками на каждой строке) заставила бы
переписывать один и тот же текст бонуса в 15 строках при каждой правке —
строки одного города со временем расходились бы, и ничто бы об этом не
сообщало. Удаление блока каскадом уносит все его ставки — строк-сирот без
города/проекта быть не может.

## Что не хранится

**Доход за смену/неделю/месяц — не колонки.** В Excel это формулы, разные у
каждого клиента; хранение готового числа означало бы держать в базе
значение, расходящееся с собственными ставками при первой же их правке.
Считается на клиенте, в чистом `rateMetrics.ts`:

```
за смену = ставка_за_час × часов_в_смене
          + ставка_за_единицу × единиц_за_смену
          + фиксированная_оплата_за_смену
          + средняя_надбавка_за_смену
итого    = за смену
неделя    = итого × смен_в_неделю(график)
месяц     = итого × смен_в_месяц(график)
```

Приоритетная ставка за час (`rate_hour_priority`) в сумму **не входит** —
это альтернативный тариф для приоритетных смен, а не доплата поверх
основного; интерфейс показывает её отдельной цифрой.

**Модель смен в неделю/месяц — усреднённая, не воспроизводит Excel
дословно.** В исходной таблице у каждого клиента свой ручной множитель (×4,
×6, ×15, ×26) — это бизнес-допущения, а не единая формула. Портал считает
по среднему количеству смен для графика (2/2 и 3/3 → 3.5/нед., 5/2 → 5,
6/1 → 6, 7/0 → 7; месяц — то же × среднее число недель в месяце). Для
графиков без регулярной кадансации (`flexible`, `parttime`) доход в
неделю/месяц не считается вовсе — показывается «—», а не оценка.

## Проекты и юр. лица — общий свободный справочник

`project` в «Ставках» — свободный текст с подсказками из
`candidate_list_options` (`list_type = project`). Изначально (TASK-008) этот
список был собственным для «Ставок» и не совпадал с enum `candidate_project`,
которым были типизированы `candidates.project`/`staffing_demand.project`/
`addresses.project` (12 значений против 30+ клиентов в исходной таблице
ставок). Миграцией `20260731120000_unify_project_free_text.sql` это
расхождение устранено: все три таблицы переведены с enum на тот же
свободный список, которым «Ставки» пользовались с самого начала — теперь
список проектов **один на весь портал**, расширяется в
«Настройки → Списки → Проекты» без миграции, и одинаково виден в
«Кандидатах», «Потребности», «Адресах» и «Ставках».

`legal_entity` — тот же принцип (`candidate_list_options`, `list_type =
legal_entity`), но остаётся специфичным для «Ставок»: у «Кандидатов»,
«Потребности» и «Адресов» такого измерения нет. `city`/`position`/`manager`
— те же справочники, что уже использует «Потребность»/«Кандидаты»/«Адреса»,
отдельных для «Ставок» не заводилось.

## Единицы измерения

Восемь значений, хранятся как `text` + `CHECK` (список проще расширить одной
миграцией, тот же приём, что `addresses.object_type`):

| Значение | Смысл |
|---|---|
| `hour` | За час |
| `hour_order` | За час + доплата за заказ |
| `hour_item` | За час + доплата за собранную единицу |
| `order` | За заказ |
| `stop` | За стоп (доставленный адрес) |
| `shift` | За смену |
| `day` | За сутки |
| `route` | За маршрутный лист |

Сдельные поля (ставка за единицу, единиц за смену) показываются в карточке
только для единиц измерения со сдельной частью (`hour_order`, `hour_item`,
`order`, `stop`).

## Дополнительные показатели

Часть клиентов в исходной таблице имеет показатели, бессмысленные у
остальных: оплата за стоп SLA 15/30+, доплата за вес и порог веса,
топливная карта, надбавка за стаж. Отдельными колонками это дало бы
десяток полей, пустых у большинства строк, и новую миграцию на каждого
следующего клиента — вместо этого произвольный список `{название,
значение}` на строке тарифа (`extras`, jsonb), редактируется прямо в
карточке.

## Условия блока — общие для всех ставок

Карточка ставки показывает секцию «Условия проекта в городе» с явным
предупреждением о числе ставок, которые разделяют этот блок: изменение
бонуса, акции или зарплатного проекта затронет все ставки блока
одновременно — это ожидаемое поведение, не побочный эффект.

## Доступ

Раздел доступен **всем четырём ролям** — как «Адреса» и «Уведомления»:
рекрутёр называет ставку кандидату на первом же созвоне, координатор и
менеджер сверяют её с условиями клиента.

## Создание, редактирование, удаление

- **Создание** — модалка «Добавить ставку»: проект, город, юр. лицо,
  должность, единица измерения, ставка за час. Блок условий находится или
  создаётся автоматически (по проекту+городу+юр. лицу); остальные тарифные
  поля и условия блока заполняются потом в карточке.
- **Редактирование** — клик по строке открывает карточку (Drawer): ставка,
  тариф с живым расчётом за смену/неделю/месяц, дополнительные показатели,
  комментарий, условия блока.
- **Удаление** — настоящий `DELETE`, не архив: у «Ставок» нет соображений
  для истории, устаревший тариф просто удаляется. Удаление строки тарифа не
  трогает блок условий; удаление блока каскадом уносит все его ставки —
  карточка предупреждает об их числе перед подтверждением.

## Известные ограничения

- Модель смен в неделю/месяц — усреднённая оценка по графику, не
  воспроизводит индивидуальные множители исходной таблицы Excel.
- Нет истории изменений тарифа (ни построчной, ни снимка «кто/когда» в
  списке — только `created_by*`/`updated_by*` на самой строке, как у
  «Адресов»).
- Подтверждение удаления — через `window.confirm` (нативный диалог браузера),
  не модалка в дизайне портала, как у остальных разделов; для удаления блока
  условий диалог называет число затрагиваемых ставок.
- Разграничения данных по проектам нет — как и везде в портале.
