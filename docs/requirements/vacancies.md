# Требования: Описание вакансий

> **Статус реализации:** справочник только для чтения. Данные статические,
> выгружены из Excel. Редактирования из интерфейса и хранения в базе нет.

## Задача раздела

Дать рекрутёру и координатору быстрый доступ к условиям по вакансии во время
разговора с кандидатом: что за работа, какие требования, сколько платят, какой
график.

Раздел отвечает на вопрос «что я могу пообещать кандидату», и по нему не
принимаются решения о численности — это задача раздела «Потребность».

## Источник данных

Файл `src/lib/portal/vacancyData.ts` — **генерируемый**, собран из Excel
«Описание вакансий». Вручную не редактируется.

Обновление данных сегодня означает: получить новый Excel → перегенерировать
файл → закоммитить → задеплоить. То есть изменение условий по вакансии
требует релиза.

## Функциональные требования (реализовано)

- Просмотр списка вакансий с фильтрацией и поиском.
- Карточка вакансии с полным описанием условий.
- Данные читаются из статического модуля, запросов к базе нет.

## Ограничения текущей реализации

- **Нельзя отредактировать вакансию из портала** — только через
  перегенерацию файла и релиз.
- **Файл попадает в клиентский бандл целиком** (около 5 900 строк) и грузится
  всем пользователям, даже если они в этот раздел не заходят. Это самая
  крупная отдельная позиция в бандле; зафиксировано в
  [`../tasks/backlog.md`](../tasks/backlog.md).
- **Нет связи с другими разделами:** вакансия не связана ни с потребностью,
  ни с кандидатом, ни со справочником должностей. Названия должностей в
  вакансиях и в справочнике `candidate_list_options` живут независимо и могут
  расходиться.
- **Нет истории изменений условий:** узнать, что платили месяц назад,
  невозможно.

## Возможное развитие (не запланировано)

Перечислено как ориентир, задачи не заведены:

1. Перенести вакансии в таблицу Supabase и дать редактирование из Настроек —
   по образцу справочников. Убирает необходимость релиза ради правки оклада.
2. Связать вакансию с должностью из общего справочника, чтобы условия
   подтягивались в карточку кандидата и в матрицу потребности.
3. Загружать раздел динамически, чтобы справочник не висел в бандле у всех.
4. Вести версионность условий с датой начала действия.
