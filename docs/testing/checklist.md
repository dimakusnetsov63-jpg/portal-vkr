# Чек-лист ручной проверки

Автоматические тесты покрывают только чистую логику (см.
[`strategy.md`](strategy.md)), поэтому интерфейс проверяется руками. Проходить
нужно **только те разделы, которых коснулась задача**, — полный прогон каждый
раз не требуется.

Портал целиком за авторизацией: нужен тестовый сотрудник, заведённый в
«Настройки → Команда и роли».

## Перед проверкой

- [ ] `npm run test` / `npx tsc --noEmit` / `npm run lint` / `npm run build` — зелёные
- [ ] `npm run dev`, открыт `http://localhost:3000`
- [ ] Открыта консоль браузера и вкладка Network

## Базовое (при любой задаче)

- [ ] В консоли нет ошибок и предупреждений React
- [ ] В Network нет запросов со статусом 4xx/5xx
- [ ] Переключение разделов в сайдбаре работает
- [ ] Обновление страницы (F5) не ломает состояние

## Потребность

- [ ] Матрица строится в три уровня: Проект → Город → Должность
- [ ] Сворачивание проекта и **отдельно** города работают независимо друг от друга
- [ ] Клик по ячейке открывает инлайн-редактирование; `Enter` сохраняет, `Escape` отменяет
- [ ] Очистка значения удаляет ячейку (значение исчезает, а не становится нулём)
- [ ] `0` сохраняется как явное «потребности нет» и отличается от пустой ячейки
- [ ] Итоги по должности, городу, проекту и колонке пересчитываются после правки
- [ ] Фильтры проект / город / должность / статус / «только заполненные» сужают выборку
- [ ] Параметры фильтров попадают в URL, страница по этому URL открывается в том же состоянии
- [ ] Навигация по неделям и кнопка «Сегодня» перемещают окно дат
- [ ] Меню «⋯» на ячейке: копирование на день / 7 дней / неделю / до даты
- [ ] «Повторить строку на следующую неделю» копирует только свою должность
- [ ] Статус и комментарий сохраняются на тройке (проект, город, должность) и не «протекают» на соседние должности
- [ ] Выпадающие списки и модалки отображаются **поверх** липких строк матрицы, а не под ними
- [ ] «История изменений» открывается и показывает записи по этой ячейке
- [ ] Массовое добавление: несколько городов × несколько должностей, счётчик показывает верное число
- [ ] При большом количестве записей появляется дополнительное подтверждение

## Авторизация и доступ

Удобно держать по тестовой учётке на каждую роль.

### Вход и выход

- [ ] Вход по логину и паролю
- [ ] Неверный пароль: «Неверный логин или пароль», в Network нет пароля в ответе
- [ ] Неавторизованный запрос к `/` уводит на `/login`
- [ ] Авторизованный запрос к `/login` уводит на `/`
- [ ] Выход завершает сессию: после него `/` снова уводит на `/login`
- [ ] Cookie `portal_session` помечена `HttpOnly` (вкладка Application)

### Управление пользователями (под руководителем)

- [ ] «Создать пользователя»: ФИО, логин, пароль, подтверждение, роль, проекты, статус
- [ ] Занятый логин подсвечивается **во время ввода**, до отправки формы
- [ ] Пароль короче 8 символов и несовпадающее подтверждение не проходят
- [ ] Новый пользователь появляется в списке и может войти
- [ ] Редактирование: ФИО, роль, проекты сохраняются; логин недоступен для правки
- [ ] Пустое поле пароля при редактировании **не** меняет пароль
- [ ] Заданный новый пароль работает, старый — нет
- [ ] Действующий пароль нигде не отображается
- [ ] Переключатель своей учётной записи задизейблен
- [ ] Последнего активного руководителя нельзя отключить и понизить в роли

### Деактивация

- [ ] Отключённый пользователь при входе видит «Учетная запись отключена администратором.»
- [ ] Уже открытая сессия отключённого прерывается: первый же переход уводит на `/login`
- [ ] Пользователь остаётся в списке, его записи в журнале на месте

### Роли и разделы

Для каждой роли — по [`../requirements/access-control.md`](../requirements/access-control.md):

- [ ] В меню видны только разрешённые разделы
- [ ] Командная палитра (⌘K) не предлагает закрытые разделы
- [ ] Прямая ссылка `/?section=<закрытый>` уводит на `/403`
- [ ] Рекрутер попадает после входа в «Адреса», а не в «Обзор» (первый доступный раздел в порядке меню)
- [ ] Координатор видит «Настройки», но не «Команду и роли» и не «Журнал»
- [ ] Смена роли применяется **без повторного входа** — после перезагрузки страницы
- [ ] Рекрутер не получает данные «Потребности» даже прямым запросом к API

### Журнал действий

- [ ] Создание, изменение, смена роли и пароля, включение и отключение попадают в журнал
- [ ] Успешные и неудачные входы фиксируются

## Известные ограничения (не считать багом)

- Данные **не обновляются автоматически**: изменения другого пользователя видны
  только после перезагрузки. Realtime не подключён.
- Разделы Обзор, Маркетинг, Аналитика работают на mock-данных — цифры там
  выдуманы и меняться от реальных действий не будут. «Описание вакансии»
  (TASK-010) переведено на реальные данные Supabase.
- Одновременное редактирование одной ячейки двумя людьми: побеждает
  сохранивший последним, предупреждения нет.
- Разграничения **по проектам** нет: роль определяет разделы, но внутри
  раздела видны данные всех проектов, включая те, что не выбраны в учётке.
- Восстановления пароля нет — забытый пароль задаёт заново руководитель.
- Панели «Интеграции», «Уведомления», «Отображение» в Настройках
  демонстрационные: переключатели не сохраняются.
- «Адреса»: документы — только внешние ссылки, файлы на сервер не
  загружаются; полной построчной истории изменений по полю пока нет, только
  снимок «кто/когда» в карточке; архивирование — без подтверждения.
- «Ставки»: истории изменений тарифа нет; удаление — подтверждение через
  нативный `window.confirm`, не модалку портала.
- «Описание вакансии»: тип поля «выбор из списка» зарезервирован в схеме, но
  редактор для него не построен (полей с этим типом не будет, пока их
  никто не создаст напрямую через API); библиотеки шаблонов вакансий нет
  (только один встроенный шаблон-затравка); история изменений — только
  снимки «кто/когда/что», не построчный diff; переупорядочивание — только
  стрелками, drag-and-drop нет.
