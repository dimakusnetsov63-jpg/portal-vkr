## Demand Module — трёхуровневая структура

**Статус:** `IN PROGRESS`
**Ветка:** влито в `main` (`ba2cbdd`)

Матрица потребности переведена на структуру **Проект → Город → Должность**.

Сделано:

- три миграции: `position` добавлен в `staffing_demand`,
  `staffing_demand_rows` и `staffing_demand_history`, ограничения уникальности
  расширены;
- статус и комментарий строки перенесены с пары (проект, город) на тройку
  (проект, город, должность);
- матрица разделена на `DemandCityGroupRow` (город) и `DemandPositionRow`
  (должность) с независимым сворачиванием;
- фильтр по должности и параметр `position` в URL;
- массовое добавление по нескольким должностям + подтверждение при большом
  количестве записей.

- [ ] ручная проверка на проде по [`../testing/checklist.md`](../testing/checklist.md)
- [ ] заменить 50 параллельных upsert'ов статуса/комментария в `AddDemandModal`

- [ ] решить, нужен ли экран истории статуса и комментария (данные пишутся,
      интерфейса нет)

## Как вести этот файл

1. Задача попадает сюда, когда над ней начали работать.
2. Крупная задача оформляется отдельным файлом по
   [`TEMPLATE.md`](TEMPLATE.md), здесь остаётся ссылка и статус.
3. Завершённая задача переносится в [`completed.md`](completed.md) с датой
   и хешем коммита — не удаляется.
