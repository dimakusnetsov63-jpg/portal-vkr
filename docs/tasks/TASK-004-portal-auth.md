# TASK-004 — Встроенная система авторизации и управления пользователями

**Статус:** `ГОТОВО К ПРИМЕНЕНИЮ` — код и миграция написаны, миграция к боевой
базе **не применялась**
**Дата:** 28 июля 2026

## Цель

Отказаться от Supabase Auth и ручного заведения сотрудников в Dashboard. Все
учётные записи создаются и управляются в разделе «Настройки → Команда и роли».
Источник истины по пользователям — база портала; Supabase остаётся базой
данных и API.

## Что сделано

### База

Миграция `20260728120000_portal_auth.sql`:

- `portal_users` (логин + bcrypt-хеш + роль + проекты + `is_active`),
  `portal_sessions` (в базе только sha256 от токена), `portal_audit_log`;
- enum `portal_user_role` (head / coordinator / manager / recruiter) и
  `portal_audit_action` (9 событий);
- функции `portal_login`, `portal_session_context`, `portal_logout`,
  `portal_admin_*`, `portal_bootstrap_admin`;
- все три таблицы закрыты RLS полностью — работа только через
  `SECURITY DEFINER` функции;
- политики данных переведены с `using (true)` на `portal_can('<раздел>')`.

### Приложение

- `src/lib/auth/` — матрица прав (`roles.ts`, покрыта тестами), сессии,
  выпуск JWT, middleware;
- `src/app/api/auth/{login,logout,token}` — три маршрута, единственный
  бэкенд проекта;
- `/login` переписан на логин+пароль, добавлена `/403`;
- `src/lib/supabase/portalUsersRepo.ts` + типы `portalAuth.types.ts`;
- `sections/settings/` — панели «Команда и роли», «Журнал действий»,
  форма создания и редактирования пользователя;
- меню, мобильная панель и командная палитра фильтруются по роли.

### Удалено

Supabase Auth целиком: `/forgot-password`, `/update-password`,
`lib/supabase/server.ts`, `lib/supabase/middleware.ts`.

## Что нужно сделать при развёртывании

Порядок важен — до шага 3 портал работать не будет.

1. **Задать `SUPABASE_JWT_SECRET`** в `.env.local` и в переменных окружения
   Vercel. Значение: Dashboard → Project Settings → API → JWT Settings →
   JWT Secret.
2. **Применить миграцию:** `npx supabase db push --linked`.
3. **Создать первого администратора** в SQL-редакторе Supabase:

   ```sql
   select public.portal_bootstrap_admin('admin', 'Имя Фамилия', '<пароль>');
   ```

   Функция работает, только пока в портале нет ни одной учётной записи.
4. **Регенерировать типы:**
   `npx supabase gen types typescript --linked > src/lib/supabase/database.types.ts`.
5. **Отключить `enable_signup`** в настройках Supabase Auth, если он ещё
   включён: сама схема `auth` больше не используется, но открытая регистрация
   в проекте — лишняя поверхность.
6. **Проверить по чек-листу** — [`../testing/checklist.md`](../testing/checklist.md),
   раздел «Авторизация и доступ».

## Проверено и не проверено

**Проверено:** `npx tsc --noEmit`, `npm run lint`, `npm test` (155 тестов),
`npm run build`. В браузере: неавторизованный запрос уводит на `/login`, форма
входа отрисовывается, недоступность RPC даёт понятную ошибку вместо падения.

**Не проверено** (требует применённой миграции и боевой базы): фактический
вход, выдача JWT и загрузка данных под ним, создание и редактирование
пользователя, переключатель активности, обрыв сессий при деактивации,
разграничение разделов по ролям, запись в журнал.

Отдельный риск, который проверяется только на реальном проекте: Supabase
должен принимать JWT, подписанный legacy-секретом (`SUPABASE_JWT_SECRET`).
Если проект переведён на асимметричные ключи подписи и legacy-секрет отозван,
вход пройдёт, а данные не загрузятся — лечится сменой способа подписи в
`src/lib/auth/jwt.ts`, остальной код не затрагивается.

## Задел на будущее

Схема рассчитана на расширение без перестройки:

- **двухфакторная авторизация** — поля в `portal_users` + шаг в `portal_login`;
- **восстановление пароля** — таблица одноразовых токенов, механика сессий
  уже есть;
- **индивидуальные права** — таблица прав на пользователя, `portal_can()`
  становится «роль ∪ индивидуальные»;
- **временная блокировка** — поле `locked_until`, проверка там же, где сейчас
  считается лимит попыток;
- **история входов** — данные уже пишутся (`login_success` / `login_failed` /
  `logout`), нужен только экран.
