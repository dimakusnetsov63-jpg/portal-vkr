# TASK-006 UI/UX Polish портала

## Цель

Портал должен ощущаться как современный SaaS: плавные переходы, предсказуемые
состояния элементов, единая типографика и палитра. Ни один сценарий работы,
ни одна цифра и ни один раздел при этом не меняются — пользователь замечает
качество интерфейса, а не новое поведение.

## Контекст

Визуальный слой был перенесён из дизайн-прототипа «как есть». Отсюда набор
проблем, накопившихся к июлю 2026:

- значения задавались на глаз: длительности `0.1s / 0.15s / 0.16s / 0.22s /
  0.25s`, размеры шрифта `10.5 / 11.5 / 12.5 / 13.5`, радиусы `7 / 8 / 9 / 10 /
  12 / 18`, высоты контролов `28 / 30 / 34 / 36 / 38`;
- один и тот же блок таблицы был скопирован в четыре файла
  (`CandidatesSection`, `AddressesSection`, `AnalyticsSection`,
  `MarketingSection`) — правка в одном месте не доезжала до остальных;
- часть интерактивных элементов не имела ни hover, ни active-состояния;
- сброс `.portal-root button { font-size: inherit }` был специфичнее `.btn`,
  поэтому шкала размеров кнопок никогда не применялась;
- загрузка показывалась текстом «Загрузка…» либо мгновенным появлением цифр.

## Границы задачи

Не меняется: архитектура, `PortalContext`, структура и состав компонентов,
SQL и Supabase, бизнес-логика, права доступа, маршруты, порядок и названия
разделов, существующий функционал.

Меняется только слой представления: токены, CSS-модули, классы в JSX и —
там, где этого требовал фиксированный футер — порядок блоков внутри
существующего компонента.

## Технические изменения

### Токены — `src/app/portal-tokens.css`

| Группа | Что появилось |
|---|---|
| Моушен | `--dur-1/2/3` (120/180/240ms), `--ease`, `--ease-out`, `--ease-in` |
| Типографика | `--fs-3xs…--fs-display` (10–26px), `--fw-*`, `--lh-*`, `--tracking-*` |
| Отступы | `--sp-1…--sp-7` (4–32px) |
| Контролы | `--control-h-xs/sm/md/lg` (24/30/36/42px) |
| Радиусы | `--radius-xs`, `--radius-control`, `--radius-pill` (в дополнение к s/m/l) |
| Границы | `--border-subtle` — для многократно повторяющихся разделителей |
| Прочее | `--ring`, `--ring-danger`, `--surface-active`, `--scrollbar-*` |

Тени `--shadow-s/m/l` переписаны двухслойными. Статусная палитра выровнена по
светлоте подложек и контрасту текста; акцент бренда `#0071e3` не тронут.

Добавлены `@keyframes portal-overlay-in`, `portal-rise`, `portal-toast-out`,
блок `prefers-reduced-motion` и аккуратный скроллбар.

**Сбросы обёрнуты в `:where()`**, чтобы иметь нулевую специфичность. Это не
косметика: без этого `.portal-root button { font-size: inherit }` (0,1,1)
перебивал `.btn` (0,1,0), и все кнопки рендерились размером с текст страницы.

### Примитивы — `src/components/portal/ui/`

- `primitives.module.css`: кнопки (sm/md/lg × default/primary/ghost/danger +
  квадратный icon), `.btnIcon*`, `.checkLabel`, общий блок таблицы
  (`.table`, `.colSticky`, `.nameCell`, `.tableScroll`, `.pager`,
  `.hscrollFake`), скелетоны, состояния форм.
- `Button.tsx`: добавлены `size="lg"`, `variant="danger"`, `icon`; прежний
  API сохранён.
- `Drawer.tsx`: проп `label`, панель всегда смонтирована и скрывается через
  `visibility` — закрытие анимируется.
- `Modal.tsx` / `CommandPalette.tsx`: одна реализация оверлея на двоих.
- `StateViews.tsx`: добавлены `SkeletonCards` и `SkeletonLines`.

### Разделы

Секционные CSS-модули оставили за собой только то, что действительно их:
`min-width` таблицы, сетку KPI, стили карточки-дровера. Остальное берётся из
примитивов.

## Что осталось и почему

- **Ручная проверка интерфейса под ролями не выполнена.** У среды разработки
  нет учётной записи портала, поэтому проверялись только `/login` и `/403`.
  Разделы за авторизацией проверены статически (сборка, типы, тесты) — нужен
  проход по [`../testing/checklist.md`](../testing/checklist.md) на реальном
  стенде, в том числе на ширинах 1920 / 1440 / 1366 / 1280 / 1024 / 768.
- **Подсветка выбранной строки таблицы не сделана.** Открытая карточка живёт
  в `PortalContext`; чтобы подсветить строку, таблице пришлось бы подписаться
  на ещё одно значение контекста и перерисовываться при каждом открытии
  дровера. Пункт 19 ТЗ это прямо запрещает — оставлено намеренно.
- **Sticky-шапка таблицы не получает тень при прокрутке.** Определить факт
  прокрутки без обработчика скролла нельзя, а это новый эффект.

## Testing

Чистая логика не затрагивалась, новых тестов нет — 170 существующих должны
проходить без изменений. Всё остальное проверяется глазами по чек-листу.

## Риски

Изменения обратимы (только слой представления), миграций нет. Основной риск —
смещения в вёрстке из-за новой шкалы размеров: базовый кегль таблиц вырос с
13.5 до 14px, кнопки впервые получили заявленные 13px. Проверять в первую
очередь широкие таблицы «Адресов» и матрицу «Потребности».
