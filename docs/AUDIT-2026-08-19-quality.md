## Что сделано правильно и переписывать не нужно

- Запись проверок **только** через `portal_save_quality_review`: у
  `quality_reviews` нет ни INSERT/UPDATE-политик, ни грантов. Итог нельзя
  прислать с клиента.
- Модель прав раздела не обходит портальную: `can_view`/`can_edit` +
  `portal_has_project` во всех политиках, права читаются из базы, не из JWT.
- Денормализация `total_score`/`group_scores` + `checklist_version` —
  прошлые оценки защищены от правок шаблона.
- Серверная пагинация и SQL-агрегат с первого дня (в отличие от
  «Кандидатов», см. BLOCK-2).
- Формула расчёта сверена с рабочими таблицами на 20 реальных строках.

## Готовность к следующим этапам

**BLOCKER для UX:** снят — DATA-01 и BUG-01 закрыты.

**BLOCKER для аналитики:** снят. Ключевой отчёт — средний процент по
каждому блоку на сотрудника — доступен из API (`portal_quality_report_by_group`);
разрез по месяцам делается вызовом на период, отдельной функцией он
появится вместе с экраном.

**Чего не хватает в данных навсегда:** знаменатель «сколько всего
самоотказов было» — он живёт в CRM и в портал не попадает, без него
«% прослушано» не посчитать ни сейчас, ни задним числом. Журнал правок
(C5) закрыт 20 августа — с этого дня история изменений оценок копится.
